Design System

Tokens to Code

Figma is the single source of truth. Variables are exported as design tokens, built to CSS by a GitHub Action, and every component here uses those tokens only.

View repository tokens.css

Workflow

From a design decision in Figma to a live component, without touching code.

  1. StructureClaude defines token layers and naming
  2. DesignFigma Variables are the source of truth
  3. ExportToken Bridge commits tokens to GitHub
  4. BuildA GitHub Action turns tokens into CSS

One token, three layers

Aliases survive the whole way from Figma into CSS.

/* Component */
--button-primary-bg-default: var(--color-action-primary-bg-default);
/* Semantic */
--color-action-primary-bg-default: var(--color-purple-600);
/* Primitive */
--color-purple-600: ;

Use it in your project

No install needed. The CSS is served straight from the public repository via jsDelivr.

  1. Add the stylesheets

    Tokens first, then the components you need. Plus the two web fonts.

    <link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Oswald:wght@500;700&family=Roboto:wght@400;500&display=swap">

<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/Tobias-Stoll/DesignSystem@main/dist/tokens.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/Tobias-Stoll/DesignSystem@main/dist/typography.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/Tobias-Stoll/DesignSystem@main/components/button.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/Tobias-Stoll/DesignSystem@main/components/input.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/Tobias-Stoll/DesignSystem@main/components/checkbox.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/Tobias-Stoll/DesignSystem@main/components/alert.css">

  2. Use the components

    Plain HTML with a class. All variants and states are on the component pages: Button, Input, Checkbox, Alert.

    <button class="btn btn--primary">Subscribe</button>

<input class="input" type="email" placeholder="you@example.com">

<label class="checkbox">
  <input type="checkbox" class="checkbox__box">
  <span class="checkbox__text">
    <span class="checkbox__label">Subscribe to the newsletter</span>
  </span>
</label>

<div class="alert alert--success" role="status">You're subscribed!</div>

<h2 class="text-heading-m">Text styles work as classes too</h2>

  3. Use tokens in your own CSS

    Every Figma variable is a CSS custom property.

    .my-card {
  background: var(--color-bg-default);
  border: var(--border-width-default) solid var(--color-border-default);
  border-radius: var(--radius-container);
  padding: var(--space-inset-lg);
  color: var(--color-fg-default);
}

Two rules

  • Use semantic or component tokens, never primitives. --color-action-primary-bg-default, not --color-purple-600. That way a design change in Figma reaches your code without edits.
  • Never change tokens in code. Figma is the source of truth: values are changed there and arrive here through the export.

Note: @main always points to the latest export, but jsDelivr may cache it for up to 12 hours. In a production project you would pin a release, for example @v1.0.0.

Atom

Alert

Shows the outcome of a whole form. Field errors stay at the field, the alert tells how it went. Uses semantic tokens directly (color/feedback/…).

Try it

Trigger an outcome. Screen readers announce it: success politely, errors right away.

All variants

As in the Figma component. Height 52px: 16 padding + 20 line height + 16 padding.

Success

You're subscribed! Check your inbox to confirm.

Danger

Something went wrong. Please try again.

When to use what

Two kinds of feedback, two places.

FeedbackWhereExample
Field errorAt the field"Please enter a valid email address."
Alert · DangerAbove the button, form stays filled"Something went wrong. Please try again."
Alert · SuccessReplaces the form"You're subscribed! Check your inbox to confirm."
