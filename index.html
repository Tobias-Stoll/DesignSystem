Design System

Design to Code - An example workflow

Figma is the single source of truth. Tokens sync to code automatically, components are read straight from Figma via the Figma MCP, and everything here is built from those tokens only.

View repository (opens in a new tab) Open in Figma (opens in a new tab) Browse all tokens

Workflow

Two paths, one source of truth. Values flow automatically, structure is read on demand.

Tokens · fully automated

  1. StructureClaude defines layers and naming
  2. DesignFigma Variables hold every value
  3. SyncToken Bridge commits tokens to GitHub
  4. BuildA GitHub Action writes tokens.css

Components · via Figma MCP

  1. DesignFigma component with bound variables
  2. ReadClaude reads it via the Figma MCP
  3. ReviewDesign QA: wrong bindings get fixed in Figma
  4. CodeExisting components are reused

Where a standard exists, use it. Where none fits, build the gap.

Figma's Variables REST API is Enterprise-only, so tokens travel through a custom plugin. For components, the Figma MCP is the standard, so it is used as is.

From Figma to a live component

How the Sign-up Card went from Figma to code. Two MCP reads, no hand-written spec.

  1. 1. Select the component in Figma

    Right-click the component set, copy the link to the selection. The link carries the node id, so only this component is read.

  2. 2. Claude reads it via the Figma MCP

    One call to get_design_context returns every state, the auto layout, the text styles and the variable bound to each layer.

  3. 3. Design QA, then read again

    The first read showed foreign library variables and mixed-up tokens that no screenshot would reveal. They were fixed in Figma, a second read confirmed it.

  4. 4. Translate into the project

    The MCP returns a React + Tailwind reference. It is adapted to this project: Form Field, Checkbox, Alert and Button are reused, only the card layout is new. Full breakdown

One token, three layers

Aliases survive the whole way from Figma into CSS.

/* Component */
--button-primary-bg-default: var(--color-action-primary-bg-default);
/* Semantic */
--color-action-primary-bg-default: var(--color-purple-600);
/* Primitive */
--color-purple-600: ;

Use it in your project

No install needed. The CSS is served straight from the public repository via jsDelivr.

  2. 2. Use the components

    Plain HTML with a class. All variants and states are on the component pages: Button, Input, Checkbox, Alert, Chip, Status Badge, Kicker, External Link, Form Field, Case Card, Info Card, Work Row, Note, Sign-up Card, Site Header, Contact Block, Site Footer.

  <span class="checkbox__text">
    <span class="checkbox__label">I want to receive the newsletter</span>
  </span>
</label>

<h2 class="text-heading-m">Text styles work as classes too</h2>

  3. 3. Use tokens in your own CSS

    Every Figma variable is a CSS custom property.

    CSS
    .my-card {
  background: var(--color-bg-default);
  border: var(--border-width-default) solid var(--color-border-default);
  border-radius: var(--radius-container);
  padding: var(--space-inset-lg);
  color: var(--color-fg-default);
}

  4. Two rules

    Use semantic or component tokens, never primitives. --color-action-primary-bg-default, not --color-purple-600. That way a design change in Figma reaches your code without edits.

    Never change tokens in code. Figma is the source of truth: values are changed there and arrive here through the export.

Note: @main always points to the latest export, but jsDelivr may cache it for up to 12 hours. In a production project you would pin a release, for example @v1.0.0.

Body L for intros and leads. Body M for everything else. Keep lines around 60 to 75 characters, so the eye finds the next line easily.

Rules

Few rules, kept every time.

RuleWhy
One Display per pageThe page title is the loudest thing. Two loud things cancel out
Body M is the default16/24 reads well on every screen. Body L only for leads, Body S for dense UI
Overline only for short labelsMono is hard to read in sentences. One to four words
Skip no heading levelScreen readers navigate by headings. The look comes from the class, the level from the structure
Line length 60 to 75 charactersSet max-width around 62ch on long text
Muted text stays above 4.5:1color/fg/muted on white is 5.1:1, color/fg/subtle only for hints and disabled

Three layers

Each layer only points to the one below. A change travels up, never sideways.

  2. –SemanticNamed by purpose, alias a primitive

Atom

External Link

Every link to another site opens in a new tab and says so before the click: with the link-out icon after the last word, and with a hidden hint for screen readers. Works on text links, buttons and whole cards. No own colors, the icon takes the color of the link.

Try it

Read the repository (opens in a new tab) or open the Figma file (opens in a new tab).

Primary (opens in a new tab) Secondary (opens in a new tab) Ghost (opens in a new tab)

When to use what

The rule is about where the link goes, not how it looks.

Link goes toBehavior
Another site (GitHub, Figma, LinkedIn, the live demo)New tab, link-out icon, hidden hint
A page or section of the same siteSame tab, no icon. Arrows (→) only for these
A file of the same site (PDF)New tab, link-out icon, the hint names the file type: "(PDF, opens in a new tab)"
Any of the above on a German pageHint in German: "(öffnet in neuem Tab)"
E-mail or phoneSame tab, no icon. The mail app opens, nothing to warn about

Accessibility

Why the icon alone is not enough.

PartWhy
Icon, aria-hidden="true"Sighted users see it before they click. Screen readers skip it, so it is not read twice
Hidden hint "(opens in a new tab)"Screen readers hear it as part of the link name. WCAG technique G201, supports 3.2.5 Change on Request
rel="noopener"The new tab cannot control this page (security)
Icon in currentColorSame contrast as the link text, in every state
